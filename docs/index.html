Install Guide

1. Requirements

  • Windows with Arc Browser installed
  • Node.js ≥ 22, pnpm 10, Git

2. Build

git clone https://github.com/deAYS/ArcBrowserMcp.git
cd ArcBrowserMcp
pnpm install
pnpm build
pnpm build:extension

3. Load the extension (unpackaged dev install)

  1. Open arc://extensions in Arc.
  2. Enable Developer mode.
  3. Load unpacked, selecting extension/dist/ from this checkout.

Or run pnpm dev:install, which builds, registers the native host, and prints these steps.

4. Connect the bridge

pnpm bridge:install
pnpm bridge:check
pnpm bridge:ping

bridge:install writes machine-specific Native Messaging files to %LOCALAPPDATA%\arc-mcp\native-host\ and registers HKCU\Software\Google\Chrome\NativeMessagingHosts\com.arc_mcp.bridge. Those files are local state — never commit them.

5. Run

pnpm start   # serve MCP over stdio
pnpm dev     # build once, then run with --watch

Uninstall

pnpm bridge:uninstall

Then remove the extension from arc://extensions.

Contribute

Workflow

git clone https://github.com/deAYS/ArcBrowserMcp.git
cd ArcBrowserMcp
pnpm install
pnpm test

pnpm test builds the extension first via pretest. Individual steps:

pnpm typecheck
pnpm build
pnpm build:extension

Focused suites: pnpm test:tabs test:navigation test:snapshot test:interactions test:page-tools test:observability test:extension-engine test:reliability. Bridge checks: pnpm bridge:check bridge:ping bridge:live-test extension:build-id extension:id extension:verify-deterministic. test:reconnect, test:release, and test:soak need a real Arc environment with the bridge loaded.

Pull requests

  • Fork, branch, keep PRs small and focused; describe what you verified.
  • Add or update tests for behavior changes; keep the deterministic extension build green.

Never commit

  • Private keys or any *.pem/*.key/*.pfx/*.p12 material (enforced by tests/release/toolsetSecurity.test.ts).
  • Generated host files (%LOCALAPPDATA%\arc-mcp\), session files, or release/ zips.
  • Secrets, tokens, or the pipe session nonce in logs and tests.

Using ArcBrowserMcp with OpenCode

Prerequisite: the Install Guide steps are done once (extension loaded in Arc, native host registered, pnpm build current).

1. Register the server

OpenCode reads .mcp.json from the project root automatically (this repo ships one). For any other project, add the server to opencode.json with absolute paths:

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "arc-mcp": {
      "type": "local",
      "command": ["node", "<absolute-path-to-repo>\\dist\\index.js"],
      "cwd": "<absolute-path-to-repo>",
      "enabled": true,
      "timeout": 60000
    }
  }
}

2. Tool permissions

Tools are named arc-mcp_<tool>, e.g. arc-mcp_browser_open_tab. One wildcard covers all 20 browser_* tools:

{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "arc-mcp_*": "allow"
  }
}

Gate writes, keep reads open:

{
  "permission": {
    "arc-mcp_*": "allow",
    "arc-mcp_browser_evaluate": "ask",
    "arc-mcp_browser_click": "ask",
    "arc-mcp_browser_fill": "ask",
    "arc-mcp_browser_type": "ask",
    "arc-mcp_browser_press_key": "ask",
    "arc-mcp_browser_navigate": "ask"
  }
}

Block everything, then opt back in:

{
  "permission": {
    "arc-mcp_*": "deny"
  }
}

Read-only: status, list_tabs, snapshot, get_text, screenshot, wait_for, console, network. State-changing: open/close/select tab, navigate, back, forward, reload, click, fill, type, press_key, evaluate.

3. Start and verify

  1. Restart OpenCode after changing config (MCP servers are loaded at startup).
  2. Run /mcp — arc-mcp should list as connected with the 20 arc-mcp_browser_* tools.
  3. The sidecar node dist/index.js starts on first use; with the extension bridge up, browser_status reports connected: true.

4. Try it

Example first prompt:

Check the browser status, open https://www.google.com in a new tab,
take a snapshot, and screenshot the page.

Under the hood that maps to browser_status → browser_open_tab → browser_snapshot → browser_screenshot. Interactions come next: snapshot, then click/fill the returned element refs.

Multiple OpenCode sessions can share the same Arc at once — requests queue through one shared bridge connection; leaving a session leaves nothing to clean up.

Using ArcBrowserMcp with Claude

Prerequisite: the Install Guide steps are done once (extension loaded in Arc, native host registered, pnpm build current).

1. Claude Code — register the server

One command from any project (recommended):

claude mcp add arc-mcp -- node "<absolute-path-to-repo>\dist\index.js"

Or commit it for the team via .mcp.json at the project root (this repo ships one):

{
  "mcpServers": {
    "arc-mcp": {
      "command": "node",
      "args": ["<absolute-path-to-repo>\\dist\\index.js"]
    }
  }
}

2. Claude Code — permissions

Put this in .claude/settings.json (or .claude/settings.local.json for just you):

{
  "permissions": {
    "allow": ["mcp__arc-mcp__*"],
    "ask": [],
    "deny": []
  }
}

Allow rules need the literal mcp__arc-mcp__ server prefix; a bare mcp__* allow is ignored. To tighten later, move write tools (e.g. mcp__arc-mcp__browser_evaluate) from allow to ask.

3. Claude Desktop

Edit %APPDATA%\Claude\claude_desktop_config.json and restart the app:

{
  "mcpServers": {
    "arc-mcp": {
      "command": "node",
      "args": ["<absolute-path-to-repo>\\dist\\index.js"]
    }
  }
}

Claude Desktop has no per-tool permission file: it asks for approval the first time a tool is used each session.

4. Start and verify

  1. Restart Claude Code / the Desktop app after changing config.
  2. In Claude Code, run /mcp — arc-mcp should show connected with 20 tools named mcp__arc-mcp__browser_*.
  3. First useful check: ask for browser_status; with Arc and the bridge running it reports connected: true.

5. Try it

Example first prompt:

Check the browser status, open https://www.google.com in a new tab,
take a snapshot, and click the search box.

That maps to browser_status → browser_open_tab → browser_snapshot → browser_click on a returned ref.
