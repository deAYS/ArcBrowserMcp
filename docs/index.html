Install Guide

1. Requirements

  • Windows with Arc Browser installed
  • Node.js ≥ 22, pnpm 10, Git

2. Build

git clone https://github.com/deAYS/ArcBrowserMcp.git
cd ArcBrowserMcp
pnpm install
pnpm build
pnpm build:extension

3. Load the extension (unpackaged dev install)

  1. Open arc://extensions in Arc.
  2. Enable Developer mode.
  3. Load unpacked, selecting extension/dist/ from this checkout.

Or run pnpm dev:install, which builds, registers the native host, and prints these steps.

4. Connect the bridge

pnpm bridge:install
pnpm bridge:check
pnpm bridge:ping

bridge:install writes machine-specific Native Messaging files to %LOCALAPPDATA%\arc-mcp\native-host\ and registers HKCU\Software\Google\Chrome\NativeMessagingHosts\com.arc_mcp.bridge. Those files are local state — never commit them.

5. Run

pnpm start   # serve MCP over stdio
pnpm dev     # build once, then run with --watch

Uninstall

pnpm bridge:uninstall

Then remove the extension from arc://extensions.

Contribute

Workflow

git clone https://github.com/deAYS/ArcBrowserMcp.git
cd ArcBrowserMcp
pnpm install
pnpm test

pnpm test builds the extension first via pretest. Individual steps:

pnpm typecheck
pnpm build
pnpm build:extension

Focused suites: pnpm test:tabs test:navigation test:snapshot test:interactions test:page-tools test:observability test:extension-engine test:reliability. Bridge checks: pnpm bridge:check bridge:ping bridge:live-test extension:build-id extension:id extension:verify-deterministic. test:reconnect, test:release, and test:soak need a real Arc environment with the bridge loaded.

Pull requests

  • Fork, branch, keep PRs small and focused; describe what you verified.
  • Add or update tests for behavior changes; keep the deterministic extension build green.

Never commit

  • Private keys or any *.pem/*.key/*.pfx/*.p12 material (enforced by tests/release/toolsetSecurity.test.ts).
  • Generated host files (%LOCALAPPDATA%\arc-mcp\), session files, or release/ zips.
  • Secrets, tokens, or the pipe session nonce in logs and tests.

Tool Access

The repo ships with all arc-mcp tools allowed. Tighten write actions to ask and keep reads on allow. Restart the client after changing config.

OpenCode (opencode.json)

Tools are named arc-mcp_<tool>, e.g. arc-mcp_browser_open_tab. One wildcard covers all 20 browser_* tools:

{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "arc-mcp_*": "allow"
  }
}

Gate writes, keep reads open:

{
  "permission": {
    "arc-mcp_*": "allow",
    "arc-mcp_browser_evaluate": "ask",
    "arc-mcp_browser_click": "ask",
    "arc-mcp_browser_fill": "ask",
    "arc-mcp_browser_type": "ask",
    "arc-mcp_browser_press_key": "ask",
    "arc-mcp_browser_navigate": "ask"
  }
}

Block everything, then opt back in:

{
  "permission": {
    "arc-mcp_*": "deny"
  }
}

Read-only: status, list_tabs, snapshot, get_text, screenshot, wait_for, console, network. State-changing: open/close/select tab, navigate, back, forward, reload, click, fill, type, press_key, evaluate.

Claude Code (.mcp.json + permissions)

Server registration lives in .mcp.json under mcpServers.arc-mcp — it carries no permissions. This mirrors the shipped OpenCode default (arc-mcp_* allow = all 20 tools); MCP tools are named mcp__arc-mcp__<tool>:

{
  "permissions": {
    "allow": ["mcp__arc-mcp__*"],
    "ask": [],
    "deny": []
  }
}

Allow rules need the literal mcp__arc-mcp__ server prefix; a bare mcp__* allow is ignored. To tighten later, move write tools (e.g. mcp__arc-mcp__browser_evaluate) from allow to ask.
